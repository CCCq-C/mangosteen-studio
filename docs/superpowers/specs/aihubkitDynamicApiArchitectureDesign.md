- 状态：第一批已实现，待用户付费验收
- 确认日期：2026-10-17
- 第一交付批次：动态模型目录 + 异步文生图 + 首页快速生图
- 上游底座：Toonflow v2.0.6

## 1. 目标与边界

山竹漫剧只保留一套 AIHubKit 接入。用户登录后，图片、视频和语言节点看到的模型都来自当前账户可用的 AIHubKit 分组与模型接口，而不是客户端内置列表。

本设计覆盖全部已提供接口的归属、依赖和扩展边界，但继续按功能逐项交付。第一批只打通共享目录基础和文生图真实链路，不同时实现视频、多模态、数字人、余额与提醒，避免一次改动多个付费链路。

## 3. 总体结构

```text
Vue 首页 / 图片节点 / 视频节点 / 语言节点
                    ↓ 只传公开参数
Toonflow 本地 Server 路由与通用生成宿主
                    ↓
AIHubKit 领域模块
├── account：登录、会话、Keychain
├── client：请求、超时、错误、响应外壳
├── catalog：分组、分组密钥、模型目录、版本
├── imageProvider：生图请求、轮询、结果映射
├── videoProvider：视频请求与结果映射（后续）
├── conversation：语言/多模态映射（后续）
├── upload：临时签名上传（后续）
└── billing：余额与提醒（后续）
                    ↓ HTTPS
          apimodel.aihubkit.com
```

依赖只能向下：界面不读取密钥，业务适配器不读取 Keychain，账户模块不理解画布节点。每个领域只维护自己的请求和响应映射，避免某个接口变更牵连整个客户端。

## 4. 共享 AIHubKit 基础

### 4.1 `client`

只负责以下通用事项：

1. 固定 Base URL、超时、JSON 解析和 HTTP 错误归一化。
2. 接收调用方传入的授权头，不自行选择账户或分组。
3. 日志只记录阶段、状态码和请求 ID，禁止记录 Cookie、Access Token、API Key、签名 URL 与完整远端响应。

### 4.2 `account`

继续作为会话唯一所有者。Keychain 会话扩展为保存账户 Access Token 和已创建的分组密钥映射；密码、验证码仍不落盘。前端只能获得公开账户信息。

### 4.3 `catalog`

目录同步采用唯一数据源：

1. 用账户会话请求 `/api/user/self/groups`。
2. 对每个可用分组复用已缓存的分组 API Key；没有时通过 `/api/token/` 创建。
3. 使用该分组 Key 请求 `/v1/models`，得到当前真实模型。
4. 根据分组元数据与已验证的模型 ID 规则分类为 `image`、`video`、`language` 或 `unknown`。
5. 生成不含任何密钥的公开目录，以及只留在 Server 内存中的模型到候选分组密钥映射。

同一模型可能存在于多个分组。公开目录只显示一次，Server 保留有序候选列表；只有远端明确返回“无可用渠道”时才尝试下一个候选，普通参数错误和额度错误不得盲目重试。

接口没有提供可靠的统一“媒体类型”字段，因此分类是当前真实未知项。无法可靠分类的模型保留在内部诊断信息中，但不进入任何可运行节点，防止把语言模型误发到图片接口。

## 5. 动态同步与删除规则

同步触发互不重叠：

| 触发点 | 行为 |
| --- | --- |
| 登录或恢复会话 | 立即同步一次 |
| 打开模型选择器 | 目录超过 10 分钟时刷新 |
| 应用保持运行 | 每 10 分钟后台刷新 |
| 用户手动刷新 | 忽略过期时间并刷新 |

同步成功后增加目录版本；同步失败保留最近一次成功目录并明确显示刷新失败，不把网络故障解释成模型被删除。

上游变更规则：

- 新增模型：下一次成功同步后自动进入匹配节点的下拉列表。
- 删除模型：下一次成功同步后直接从下拉列表消失，不显示“不可用”。
- 旧节点已选被删模型：把节点的模型字段清为空字符串，不自动替换成其他模型。
- 空模型运行：节点停止在本地校验阶段，提示“这个节点的模型已失效，请重新选择模型”，不产生付费请求。
- 删除分组：移除该分组映射，不远程删除历史 Token；相同模型若仍有其他分组候选则继续可用。
- 新节点首次打开：可默认选当前目录第一个可用模型；旧节点失效时绝不默认迁移。

## 6. 生图适配器

第一批沿用 Toonflow 已有媒体 Provider 协议，只增加内置 `aiHubKit` Provider，不另建第二套生成系统。

### 6.1 文生图主链路

1. 节点传入模型、提示词、数量和可选尺寸。
2. Server 根据模型 ID 取得分组密钥候选，不把密钥返回 Web。
3. Provider 调用 `POST /v1/images/generations/tasks`。
4. 从兼容响应形态中提取任务 ID，调用 `GET /v1/images/generations/tasks/{taskId}` 轮询。
5. 成功时提取图片 URL，交回既有生成宿主下载到项目 `assets/generated`，画布节点保存本地资产引用。
6. 异步端点只有在 404 或 405 时才回退 `POST /v1/images/generations`；其他错误原样返回，避免重复扣费。

轮询支持取消，间隔 3 秒，总时限 30 分钟。响应文档未给出完整 Schema，因此任务 ID、状态、错误和产物采用有限的兼容提取器；无法识别的响应报协议错误，不猜测成功。

### 6.2 图生图边界

后续仍放在同一 Provider，但 multipart 构造、重复 `image` 字段、可选 `mask` 和尺寸校验单独封装，不让文生图承担文件上传职责。

## 7. 首页快速生图

首页与画布复用同一个图片节点和同一个生成动作：

1. 用户输入提示词并提交。
2. 创建项目并进入工作台。
3. 画布读取一次性的待执行快速生图请求，新增 `remote-imageGenerationNode`。
4. 节点写入提示词和当前有效默认图片模型。
5. 直接调用节点已有的 `generateImage` 工具，进度和结果都显示在画布节点中。

待执行请求只存在于当前客户端状态，消费后立即删除；不把 `autoGenerate` 写入画布，避免崩溃恢复或再次打开项目时重复产生付费任务。

## 8. 其他接口的独立归属

### 8.1 视频

视频 Provider 独立于图片 Provider。它负责 duration、resolution、ratio、参考媒体、首尾帧以及任务状态。存在首帧或尾帧时不发送 ratio；首尾帧与参考媒体互斥。首尾帧只对文档明确支持的模型和分组开放。

### 8.2 语言与多模态

语言目录与图片、视频共用 `catalog`，请求映射由 `conversation` 独立负责。当前正式文档定义 `/v1/chat/completions`，而旧山竹实现曾使用 `/v1/responses`；在真实调用确认前不做自动混用，也不把兼容判断散落到语言节点。

### 8.3 临时文件

`upload` 只服务需要远程 URL 的视频与数字人：先获取签名 PUT/GET 信息，再使用返回的精确 Header 上传原始字节，最后把临时 GET URL 交给任务接口。签名信息只驻留内存。

### 8.4 数字人

总览要求视频与 5 秒至 20 分钟音频；详细接口又把 `height`、`width`、`num_frames`、`frame_rate` 标为必填，但示例没有这些字段。这是文档矛盾，必须通过真实接口或上游确认后再实现，不能自行猜参数。

### 8.5 余额与提醒

`billing` 使用 `/api/user/self_v2` 查询额度并负责文档规定的换算，提醒通过 `/api/user/setting` 保存。它不参与模型目录和生成任务，避免账户展示逻辑影响生成链路。

## 9. 错误、安全与一致性

| 类别 | 示例 | 行为 |
| --- | --- | --- |
| 本地配置 | 未选模型、提示词为空、引用缺失 | 节点原地报错，不发远程请求 |
| 账户授权 | 会话或分组 Key 失效 | 刷新一次目录/密钥；仍失败则要求重新登录 |
| 上游业务 | 参数非法、余额不足、模型不支持 | 显示上游可读错误，不换模型重试 |
| 网络 | 超时、DNS、TLS | 保留节点输入和最近成功目录，允许手动重试 |
| 协议 | 缺任务 ID、未知状态、无产物 | 标记协议错误并保留有限诊断，不猜结果 |

任何 Cookie、Token、API Key、密码、验证码和签名 URL 都不得进入 Git、前端状态、工作区画布或普通日志。

## 10. 第一批验收

1. 登录后能从当前账户同步图片模型；上游新增和删除在刷新后准确反映。
2. 已保存节点的模型被删除后字段变空，界面不出现“不可用”占位；运行被本地阻止并提示重新选择。
3. 图片节点可以使用动态模型完成一次异步文生图，产物落入当前项目并显示在节点。
4. 首页快速生图能创建项目、进入画布、创建图片节点并调用同一生成链路。
5. Server、Web、Desktop 的既有类型检查和构建通过；真实付费生成只在用户明确执行时验收。

## 12. 2026-10-18 视频参考图与能力自动同步

本批只打通“本地图片作为普通参考素材生成视频”，不同时开放参考视频、参考音频或首尾帧，避免不同输入协议互相混用。

视频参考能力按以下优先级合并：

1. 当前账号定价目录中的模型介绍。介绍明确写出 `9图3视频3音频`、`支持3图` 或 `30图0视频10音频` 时，逐项采用模型自己的数量；明确的 `0` 不能被系列默认值覆盖。
2. 生视频官方文档中的系列规则。当前用于补齐介绍未写数量的 Seedance 2.0 与 Seedance 2.5 别名；文档每次启动自动检查，运行期间与模型目录一样按十分钟周期刷新。
3. 当前账号最近一次成功的规范化规则快照。断网或文档临时不可用时继续使用，不保存原始网页、Cookie、Token、API Key 或签名地址。
4. 仍无法确定能力的模型只保留文生视频，不猜测支持参考图；新介绍或新系列规则同步成功后自动开放。

节点只根据合并后的图片上限声明 `imageReference:N`。本地参考图由 Server 读取为受限内存数据，AIHubKit Provider 使用账户 Access Token 调用临时文件接口，按返回的签名地址上传原始字节，再把临时 HTTPS 地址作为 `referenceImages` 发送给视频任务。Access Token 与签名地址只留在 Server 内存，不进入前端、画布、日志或本地规则快照。

发送前继续执行两层校验：节点按模型能力阻止超量素材；Provider 校验输入类型、大小、上传响应和 HTTPS 地址。临时上传失败时不创建视频任务，因此不会产生视频生成费用。
