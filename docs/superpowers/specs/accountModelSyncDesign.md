# 账号模型同步设计

## 目标

在不跨账号复用分组密钥的前提下，避免同一账号重复创建山竹分组密钥，并把 21 个左右分组的首次模型同步从约 5 分钟缩短到约 35–70 秒。模型是否展示仍以当前账号对应分组的 `/v1/models` 实际结果为准。

## 账号与密钥边界

密钥分为两层保存：

1. 活跃登录会话继续保存当前账号的 Cookie、Access Token 与当前可用分组密钥。
2. 系统钥匙串增加按用户 ID 隔离的分组密钥库，退出登录时只删除活跃会话，不删除该账号自己的分组密钥库。

登录账号 B 时只能读取 B 的密钥库；切回账号 A 时恢复 A 的密钥。不同账号之间没有回退、合并或替代关系。

## 防重复创建顺序

对于缺少本地密钥的分组，必须依次执行：

1. 查询当前账号的 `/api/token/` 密钥列表。
2. 仅匹配名称为 `山竹漫剧-{group}`、分组相同且状态可用的山竹自建密钥，不接管用户手工创建的其他密钥。
3. 通过批量取回接口获取完整密钥；批量接口不可用时退回逐个取回。
4. 只有成功确认上游不存在可复用密钥后才允许调用 `POST /api/token/` 创建。

上游密钥盘点失败时保留已同步模型并稍后重试，不冒险重复创建。

## 加速策略

- 已有密钥的 `/v1/models` 查询使用最大并发 4。
- 新密钥每轮最多创建 3 个，创建动作保持串行并间隔 300 毫秒。
- 第一轮优先选择可识别的文本、图片、视频分组各一个，其余分组保持上游顺序。
- 部分目录的自动继续间隔从 15 秒改为 3 秒；遇到 429 或上游错误时保留服务端已有退避和下一轮重试。
- 前端持续显示 `已同步 X / Y 个渠道`，只让已经通过 `/v1/models` 验证的模型进入选择器。

## 状态与失败处理

- 切换账号会使当前目录失效，旧请求通过 epoch 检查退出，不能覆盖新账号目录。
- 某个分组失败不会清空其他成功分组；有上一轮同账号缓存时继续展示缓存。
- 已删除或失效密钥收到 401 后从当前账号密钥库移除，并在下一轮重新盘点，不直接跨过盘点创建。
- 上游删除模型后，下一次成功目录中不再出现；旧节点保留模型 ID，但选择器留空并由现有节点校验提示重新选择。

## 验收标准

1. 重启应用或退出后重新登录同一账号，不新增已存在的山竹分组密钥。
2. 切换不同账号时，不读取或使用前一个账号的分组密钥。
3. 新账号能先看到文本、图片、视频三个类别的首批真实模型，随后自动补齐。
4. 模型目录页面显示实时分组进度，部分同步期间已成功模型可正常选择。
5. 全仓类型检查、Web 构建与 Server 构建通过；不新增测试模块。
